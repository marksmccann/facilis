## Define a format once, use it anywhere.

Formats are plain definitions. Factory helpers cover common authoring patterns,
like filtering input into semantic groups and inserting literal separators. The
definition stays free of DOM events, component state, and framework lifecycle
details, so the same format can be mounted wherever you need it.

<HomePrimaryExample>
<div slot="snippet">

```ts
import { defineSegmentedFormat } from 'facilis';

export const creditCard = () =>
    defineSegmentedFormat({
        matches: /\d/,
        segments: [4, ' ', 4, ' ', 4, ' ', 4],
    });
```

</div>

<HomeCreditCardDemo />

</HomePrimaryExample>

The demo uses the same factory-built format as the code above. Adapters are
intentionally thin: they connect real inputs to the runtime hooks while your
format keeps the behavior in one place.

<Tabs>
    <TabItem label="DOM">

```ts
import { bindFormat } from 'facilis-dom';
import { creditCard } from './formats/creditCard';

const cleanup = bindFormat('#credit-card', creditCard());
```

    </TabItem>
    <TabItem label="React">

```tsx
import { useFormat } from 'facilis-react';
import { creditCard } from './formats/creditCard';

function CreditCardField() {
    const card = useFormat(creditCard);

    return <input {...card.inputProps} />;
}
```

    </TabItem>

</Tabs>

The core package owns formatting behavior. Adapter packages own the wiring:
reading input state, running the format, writing the next value, and preserving
selection when needed.

## Use ours or compose your own.

Start with first-party formats for common fields, reach for factory helpers when
a reusable shape fits, and use `defineFormat()` when the field has its own
rules.

```ts
import { currency, number, pattern, phoneNumber } from 'facilis-formats';

const sku = pattern('aa-####');
const quantity = number({ min: 0, thousandsSeparator: ',' });
const price = currency({ includeCents: true });
const contactPhone = phoneNumber();
```

First-party formats are built from the same core ideas as your own formats, so
they can sit beside custom definitions instead of becoming a separate system to
learn.
