## Define the format once.

Formats are plain definitions. They describe how to normalize input, how to
display the normalized value, and what should happen when the field blurs. The
definition stays free of DOM events, component state, and framework lifecycle
details.

```ts
import { defineFormat } from 'facilis';

export const accessCode = () =>
    defineFormat({
        normalize(raw) {
            return raw.replace(/[^a-z0-9]/gi, '').toUpperCase().slice(0, 8);
        },
        format(normalized) {
            return normalized.replace(/(.{4})(?=.)/g, '$1-');
        },
    });
```

`defineFormat()` creates a portable format instance. The same behavior can be
mounted by an adapter, reused in another project, or tested directly without a
browser.

## Use the format everywhere.

Adapters are intentionally thin. They connect real inputs to the same runtime
hooks, while your format keeps the behavior in one place.

<Tabs>
    <TabItem label="DOM">

```ts
import { bindFormat } from 'facilis-dom';
import { accessCode } from './formats/accessCode';

const cleanup = bindFormat('#access-code', accessCode());
```

    </TabItem>
    <TabItem label="React">

```tsx
import { useFormat } from 'facilis-react';
import { accessCode } from './formats/accessCode';

function AccessCodeField() {
    const code = useFormat(accessCode);

    return <input {...code.inputProps} />;
}
```

    </TabItem>
</Tabs>

The core package owns formatting behavior. Adapter packages own the wiring:
reading input state, running the format, writing the next value, and preserving
selection when needed.

## Use ours or compose your own.

Start with first-party formats for common fields, reach for `pattern()` when a
tokenized layout is enough, and use `defineFormat()` when the field has its own
rules.

```ts
import { currency, number, pattern, phoneNumber } from 'facilis-formats';

const sku = pattern('aa-####');
const quantity = number({ min: 0, thousandsSeparator: ',' });
const price = currency({ includeCents: true });
const contactPhone = phoneNumber();
```

First-party formats are built from the same core ideas as your own formats, so
they can sit beside custom definitions instead of becoming a separate system to
learn.
